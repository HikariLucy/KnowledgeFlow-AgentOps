# Hito 3: agregación de métricas — plan

Objetivo: persistir los eventos sanitizados existentes y ofrecer consultas locales de lectura para el futuro dashboard. Especificación: solicitud Hito 3 y docs/12-observabilidad.md.

Arquitectura: SQLite estándar, una tabla de eventos con JSON canónico e índices sobre dimensiones de consulta. Rotación lógica de eventos más antiguos, retención temporal y techo físico de páginas; sin copias JSONL adicionales al habilitar almacenamiento. API administrativa con clave independiente, sin session_id. Calidad tiene contrato separado con evidencia de benchmark; no se deduce de spans.

Alternativas consideradas: JSONL rotado requiere escanear archivos e índices paralelos; collector externo añade servicios y dependencias. SQLite permite consultas indexadas y transacciones con dependencias existentes. Decisión de implementación dentro del alcance autorizado.

Restricciones: no frontend, proveedores reales, cambios de agentes, nuevas dependencias, push ni merge. Preservar cambios previos sin commit automático.

## Riesgos a verificar

- Logs no cuentan como spans; HTTP y agente tienen denominadores distintos.
- Tokens parciales: suma observada con cobertura; nunca convertir desconocidos en cero.
- Retención puede cortar trazas; paginación estable por secuencia, no snapshot entre páginas.
- SQLite lleno/bloqueado: pérdida visible y negocio preservado.
- Credenciales y datos libres no aparecen en respuestas, ni siquiera errores de validación.
